# SidecarSwitch のアーキテクチャと設計

[繁體中文](ARCHITECTURE.md) | [English](ARCHITECTURE.en.md) | **日本語** · [ドキュメント](README.ja.md)

SidecarSwitch は、モニターなしの Mac mini + iPad 環境を想定した、規則に基づくディスプレイ状態管理システムです。

## 設計原則

1. **物理モニター優先：** 自動モードで有効な手動指定がない場合、物理モニターを優先し、Sidecar 接続を開始しません。他のモードはそれぞれの方針で判断し、即時切り替えは保証しません。
2. **手動操作優先：** iPad をサブ画面にするなどの指定は、現在のハードウェア構成内で優先されます。モード変更、リセット、構成変更で再評価します。
3. **状態の可視化：** 判断と観測した状態をアトミックに保存します。メニューと GUI はスナップショットを読み、メニュー読み取り時に重い検索を行いません。
4. **失敗からの復旧：** デバウンス、再試行回数の制限、クールダウンで連続接続要求を抑えます。外部サービスが常に正常に動作する保証ではありません。

## 構成

```text
Swift / AppKit + SwiftUI SidecarSwitch.app
  ├─ SwiftUI settings → shared CLI/config transactions
  ├─ menu-json → core/menu.py → config.json + atomic status.json + daemon liveness
  └─ CLI argument arrays → sidecarswitch-cli → Unix socket → sidecarswitchd
                                                       ├─ Detector / IOKit / CoreGraphics
                                                       └─ StateEngine → BetterDisplay CLI
```

メニューは 1 秒ごとにスナップショットの変更を確認し、変更がある場合、または前回読み取りから 5 秒経過した場合に `menu-json` を呼びます。メニューの読み取りではハードウェアを検索しません。CLI 子プロセスは AppKit のメインスレッドをブロックせず、メニュー展開中は再構築せずに閉じた後で更新します。操作は引数配列と許可リストを使い、デバイス名を shell コマンドへ埋め込みません。ログイン起動は `SMAppService.agent` が管理するアプリ内の LaunchAgent を使い、相対パスのネイティブ実行ファイルから選択した Python を起動します。外部の起動 plist は作成しません。Python は子プロセスとして動作し、正常終了では再起動せず、異常終了時は launchd がサービスを再起動します。ネイティブサービスはアプリの移動イベントを監視し、ゴミ箱への移動時に登録を解除して終了します。 ロックでメニューの重複起動を防ぎます。ディスプレイ自動化の停止ではメニューを残し、終了操作ではメニューも閉じます。有効なログインサービスは削除の監視を継続します。

## 主な仕組み

### 1. ハードウェア構成の世代管理

物理モニターがない状態で iPad をサブ画面に指定しても、定期評価が直後にメインへ戻してはいけません。手動指定を構成の世代に関連付け、通常の評価では維持します。構成変更、モード変更、リセットで無効になります。物理モニターがある場合、iPad 接続の消失によってメイン・サブ指定が解除されることもあります。

グローバルショートカットと手動のみモードでのメイン・サブ接続要求は、1 回の試行サイクルに限り有効です。終了後に要求を解除し、確立した接続は維持します。手動のみモードでは、その後の切断やデバイスの再検出で自動再接続しません。

### 2. 状態遷移の直列化

USB、画面イベント、30 秒ごとの watchdog が同時に到着しても、共通ロックで評価と設定トランザクションを直列化し、重複した通知をまとめます。SidecarSwitch 自身の競合を防ぐ仕組みであり、他のアプリによる同時制御は起こり得ます。

### 3. デバウンスとクールダウン

- 物理モニターが消失すると 4 秒の待機を開始し、その間に復帰すれば切り替えを中止します。一時的な信号変化による不要な iPad 起動を抑えますが、すべての画面障害を防ぐものではありません。
- Sidecar 接続は最大 3 回、間隔 3 秒で試行します。上限に達すると一度だけ通知し、予備画面を維持します。30 秒のクールダウン終了だけでは再試行を再開しません。対象 iPad の USB／Sidecar 検出が「なし」から「あり」に変わるか、手動で再接続／リセットする必要があります。照会エラー、通常の USB 通知、物理モニターの接続変更では停止を解除しません。

### 4. 仮想ディスプレイと安全な切り替え

- 物理モニターがない場合は、設定済みの BetterDisplay 仮想画面（通常は `SidecarSwitchVirtual`）でデスクトップを維持し、iPad がメインになった後も接続を保持します。Sidecar の接続成功だけでは仮想画面を切断しません。
- 検出器は、正常な解像度とハードウェアまたは BetterDisplay の識別情報を持つオンラインの物理画面を保持します。一時的に inactive、またはミラー元を取得できない場合も対象です。利用可能かどうかは `is_active` と `mirror_source_id` で別途判定し、0／1 ピクセルの仮画面は引き続き除外します。
- 共通の物理画面への切り替え処理は、既存の物理メイン画面を優先し、UUID（取得できなければ名前）で対象を固定します。仮想画面や Sidecar とのミラー依存を解除し、同じ物理画面がアクティブなメイン画面として独立して使えることを再確認してから、設定済みの仮想画面を切断します。iPad の切断要求では、仮想画面がオフになったことも確認してから Sidecar を切断し、その後で元の物理画面を再確認します。
- 切断前に代替画面を確認できなければ、iPad の接続を維持します。切断後にすべての物理画面が消え、回数制限付きの復旧に失敗した場合は、照会が正常で対象も変わっていないことを確認し、元の iPad への再接続を 1 回だけ試みます。再接続に成功しても切断失敗のエラーを保持し、明示的な操作、モード変更、リセットまでバックグラウンドでの再試行を停止します。接続の復旧を切断成功とは扱いません。
- 手動モードでは、明示的な要求がなければ `NO_CHANGE` を返し、モニターの抜き差しだけでは切り替えません。別途有効にした起動時接続は後述の規則に従います。操作をキャンセルすると、それ以降の仮想画面の切断、Sidecar 切断、復旧のための再接続は行いません。

Screen Sharing/VNC や SSH による復旧は事前に自分で設定してください。SidecarSwitch はリモートアクセスを有効化せず、SSH 自体は仮想ディスプレイを必要としません。

### 5. アトミックな状態保存

- daemon は実際の状態、目標状態、判断理由を一時ファイルへ書き、`os.replace` で `~/Library/Application Support/SidecarSwitch/runtime/status.json` をアトミックに置き換えます。
- `core/menu.py` と GUI が読み取ります。設定リビジョンの不一致や古いデータでは関連操作を無効にし、不明な状態を保持します。メニューの更新操作だけが CLI 経由でハードウェア状態の更新を要求します。

## USB イベントと一時的な操作対象

`core/usb_events.py` は ctypes で IOKit の `IOUSBHostDevice` first-match/terminated 通知を登録します。コールバックは iterator の内容を処理・解放した後、起動イベントを設定するだけです。daemon の共通ループが通知、起動時探索、watchdog を処理し、既存の `StateEngine.evaluate` を呼びます。ネイティブコールバック内で BetterDisplay を実行しません。停止時は RunLoop source、iterator、notification port を解放します。登録失敗時も watchdog は継続し、診断を出します。

`usb_event_wakeup` と `auto_detect_ipad` の既定値は true です。既存の設定トランザクションで保存・即時反映し、最初は折りたたまれた詳細設定内に両スイッチを配置します。保存済みの無効設定は保持します。設定変更と状態遷移は評価ロックを共有し、処理中に対象が置き換わることを防ぎます。

自動検出は Sidecar UUID を持つ明示的なペアリングを優先します。その場合 USB 接続は必須ではなく、候補一覧から一時的に消えても別の対象へ変えません。有効な指定がない場合だけ、単一の USB 候補から推定します。結果は `ActualState.resolved_ipad` に置き、接続、切断、再接続、メイン画面操作で共有します。USB シリアルと Sidecar UUID は構成の識別に含め、デバイス変更時に手動指定を無効化します。

推定では Config やペアリング一覧を書き換えません。照会が不完全、または候補が曖昧なら接続を開始しません。保存済み USB/Sidecar 対応を優先し、なければ単一候補を推定しますが、同一機器である証明にはなりません。GUI とメニューは現在の操作対象を表示し、指定済みペアリングの操作は送信前に再確認します。他のペアリングは先に操作対象へ設定する必要があります。

通知 API の参照先：[Apple IOServiceAddMatchingNotification](https://developer.apple.com/documentation/iokit/1514362-ioserviceaddmatchingnotification) とローカル macOS SDK の `IOKitLib.h`。即時なのは通知と評価の起動であり、Sidecar 接続完了は探索、実行中の操作、再試行、デバウンスにも左右されます。

## 設定の整合性と不明な状態

主設定・状態ファイルと `/tmp/SidecarSwitch` の代替先は、最終書き込み時刻による選択規則を共用し、読み取り前に所有者とファイル種別を確認します。無効な設定では既定値を適用せず起動を拒否し、GUI は保存を無効化して原本を保持します。GUI 取引は `expected_revision` を送り、名前の下書きは編集開始時の版を保持します。競合後は再確認して保存します。

検出器は確認済みの Sidecar session UUID と display UUID の対応を実行中だけ保持します。探索候補が消失しても対応を使い、対象変更または切断確認時に消去します。`ActualState.sidecar_display_id` をメイン画面選択と充足判定で共用します。接続中でも画面を識別できない場合は不明として現在の表示を維持します。同じ観測内で後の identifiers 照会が成功しても、先の失敗は消去しません。

## グローバル接続ショートカット

「設定とペアリング → 動作と設定 → グローバルショートカット」でキー欄をクリックし、組み合わせを押してから保存します。Control または Command を含めてください。英字、数字、一般的な記号、矢印／移動キー、F1–F20 に対応します。Esc またはウインドウの切り替えで記録をキャンセルできます。記録中は既存のグローバルショートカットを一時停止し、キャンセル後に復元します。保存前は登録せず、変更や無効化も可能です。Mac に直接接続したキーボードを使用し、Mac にログインしてロックを解除し、SidecarSwitch のメニューアプリとバックグラウンドサービスを起動しておきます。ロック画面ではショートカットを使用できません。物理モニターや設定ウインドウは不要です。

- 手動モードは通常、ショートカットまたはメニューからの明示的な操作のみ受け付けます。「起動時にモニターがなければ iPad に自動接続」を選ぶと、各起動セッションのサービス初回起動時に 1 サイクルだけ要求できます。約 2 秒の検出間隔を維持し、1 回 30 秒で最大 3 回（合計最大 90 秒）探索します。見つからなければ起動時接続の処理を停止します。物理モニターがなく、iPad の対象を識別できた場合に接続を開始します。モニターの存在、利用者の操作、設定の無効化、時間切れで中止します。同じ起動セッションでアプリやサービスを再起動しても再試行しません。ログイン時に実行するにはログイン自動起動を有効にしてください。ログイン前には接続できません。
- 新規導入では手動モードと起動時接続が既定で有効です。更新時は既存のモードを保持します。設定とメニューバーは手動、自動の順に表示します。
- 自動モードは従来の自動接続を維持し、ショートカットで回数制限付きの接続要求を開始します。
- 手動モードでは成功、失敗、キャンセルでそのサイクルは終了し、その後の切断、USB イベント、iPad の再検出では自動接続しません。
- 1 回の要求は従来どおり最大 3 回と既存の再試行間隔を使用します。長押しや処理中の連打で回数は増えません。終了後に再度押すと新しい要求を開始できます。
- 物理モニターがなければ iPad を主画面、あれば副画面にします。iPad 優先モードでは主画面を維持します。すでに接続され画面が利用可能な iPad は切断や役割変更を行いません。
- 保存は既存の設定リビジョン検証と CLI／IPC を使用し、装置スキャンや接続を行いません。登録競合時は別の組み合わせを案内し、失敗ダイアログは表示しません。ただし Sidecar 自体の接続失敗警告は引き続き表示される可能性があります。

macOS 標準のショートカット登録を使用し、追加パッケージやキーボード監視のアクセシビリティ権限は不要です。キーは物理位置で識別するため、入力ソースを切り替えても同じ組み合わせを使用できます。

現状では iPad が Sidecar に接続できるか事前に確定できません。自動モードの下に別行で、接続できないときは自動試行によって macOS の警告ウインドウが頻繁に表示される可能性を案内します。利用可能な機器の一覧や USB 検出は、接続成功の保証ではありません。
